## RESOLVED (2026-09-05): the anti-correlation does not reach the audited models

The previous commit flagged the soundness lens's finding as the first thing to check on
resume, because if chi* were anti-correlated with entanglement on the *shipped* models it
would be a question about the paper's headline instrument rather than about this control.
It is not. Checked three ways.

**1. The mechanism needs a high-weight readout, and no shipped model has one.** The
control read out the maximal-weight Pauli. A weight-n Pauli maps every computational-basis
branch onto a different branch, so on a state supported on a subset of branches -- exactly
what a low-chi truncation produces -- each term pairs a retained amplitude with a
discarded one and the readout cancels to *exactly* zero, whatever the fidelity. Measured
max Pauli weight over every audited model, by calling `audit_units` on a real example:

    vqc_text  n=6  1 unit   1 obs   weight 1
    qsann     n=2  9 units 24 obs   weight 1
    qmsan     n=2  9 units  6 obs   weight 1
    claqs     n=8  1 unit  24 obs   weight 1
    discocat  n=9  1 unit   0 obs   no Pauli readout (post-selected Born rule)

Worst weight across the whole zoo is 1. This is now pinned by
`tests/test_readout_weight.py`, which also reproduces the cancellation on GHZ so the
failure mode stays documented rather than rediscovered.

**2. Empirically, chi* is positively correlated with infidelity, not anti-correlated.**
Scanning all 188 stored runs that record a chi=1 fidelity:

    mean F@chi=1 for runs certified chi*=1 : 0.655  (n=162)
    mean F@chi=1 for runs certified chi*=2 : 0.223  (n=26)

The instrument fires (chi*>1) precisely where the product surrogate is *far* from the true
state, which is the correct direction. The control's signature -- chi*=1 certified at
near-zero fidelity while a near-product state escapes the grid -- does not appear.

**3. The `2 sqrt(1-F)` bound is real but weak, and is not what carries the argument.**
With ||O||=1 it gives |<O>_psi - <O>_phi| <= 2 sqrt(1-F), but at F=0.016 that permits a
full swing, so it does *not* on its own forbid a weight-1 readout from agreeing at low
fidelity. What rules the pathology out for this paper is (1) plus (2), not the bound.

### The finding that survives, and it is a feature

Many runs do certify chi*=1 at low state fidelity -- most sharply `vqc_text/sst2` at n=16,
where F@chi=1 = 0.122 while the product surrogate reproduces **100%** of the test
predictions. That is not the pathology; it is the paper's thesis stated at its strongest:
the trained state is genuinely far from a product state, and the decisions still do not
need the difference. chi* is a decision-level metric by construction (the abstract defines
it as recovering "the model's own predictions"), and Figure 2's two panels already make
the fidelity-vs-agreement split explicit.

**Available strengthening, not yet written into the paper:** the n=16 pair (F=0.122,
agreement=1.000) and the chi*=1 vs chi*=2 fidelity split above together answer the
referee objection this whole study was chartered to answer -- "the instrument may simply
always report chi*=1" -- from *shipped data*, without a synthetic control. The instrument
reports chi*=2 on 26 of 188 runs, and does so exactly where fidelity is low.

### What remains for a positive control

The k-of-m dial proposed by the referee lens below was the design adopted, and it is now
built and passing; what follows is the specification it was built from: fix n, architecture, wire order and readout weight, entangle
only k of m pairs, and check that measured chi* tracks 2^k for k=0..4. Note that both
adversarial lenses independently rejected the candidate design, for different reasons
(soundness: the mechanism is not entanglement; referee: the three-point ladder varies wire
labelling, not physical resource). Any resumed work should start from the k-of-m dial and
the two-point acceptance test in Result 11's `fix` field, not from the design as written.

## 0. There is no `AuditUnit` class

The task brief calls it "AuditUnit"; in the code the auditable unit **is `BoundCircuit`**, defined at `<repo>/src/simcert/circuits/ir.py:13`:

```python
@dataclass
class BoundCircuit:
    n_qubits: int
    qasm: str = ""  # OpenQASM 2.0, state-prep only; empty when `state` is supplied directly
    observables: list[dict[int, str]] = field(default_factory=list)  # readout Pauli-dicts
    label: int | None = None
    meta: dict = field(default_factory=dict)
    state: object = None  # np.ndarray | None

    def qfunc(self):
        import pennylane as qml
        loaded = qml.from_qasm(self.qasm)
        def _apply():
            loaded()
        return _apply
```

The pipeline consumes it **duck-typed** — it only ever touches `.state`, `.qfunc()`, `.n_qubits`, `.observables` (`<repo>/src/simcert/audit/pipeline.py:44-51`). `label` and `meta` are carried for provenance only and are *not* read by `audit_model`.

Two supply routes, mutually exclusive:

- **QASM route** — set `qasm=qfunc_to_qasm(qf, n)`; the audit rebuilds the qfunc via `qml.from_qasm` and gets the statevector with `exact_statevector`. Used by `vqc_text`, `qsann`, `qmsan`, `discocat`.
- **State route** — set `qasm=""`, `state=<np.ndarray of shape (2**n,)>`. The audit skips PennyLane entirely. Used by `claqs` (`<repo>/src/simcert/models/claqs.py:217-220`):

```python
def audit_units(self, example) -> list[BoundCircuit]:
    obs = [{i: p} for i in range(self.q) for p in ("X", "Y", "Z")]
    return [BoundCircuit(n_qubits=self.q, qasm="", observables=obs,
                         label=int(example.label), state=self._state_np(example))]
```

The dispatch is literally one ternary in the pipeline:

```python
run_chi_sweep(
    None if u.state is not None else u.qfunc(),
    u.n_qubits, u.observables, chi_values, cutoff, full_state=u.state,
)
```

**Design consequence:** a positive control need not emit QASM at all. If the state-prep is easier to express as a direct amplitude construction (or if you want to skip the `qml.from_qasm` round-trip cost per example), the state route is fully supported and already exercised by a shipped model. `state` is explicitly transient/not serialised.

`observables` are Pauli-dicts `{wire: 'X'|'Y'|'Z'}`, wires absent = identity. Evaluated by `pauli_expval` directly on the dense state in `O(2**n)` — **no 2^n × 2^n matrix is ever built** (`<repo>/src/simcert/audit/observables.py:19-57`). Wire convention: **wire 0 is the most-significant qubit**, amplitude index `sum_w bit_w * 2**(n-1-w)`. This matters for a control whose readout is a specific multi-qubit Pauli.

Note an observable dict *can* be multi-qubit: `{0:"Z", 3:"Z", 7:"Z"}` is a valid tensor-product Pauli and `apply_pauli` handles it. Nothing forces single-qubit readouts. This is the single most important degree of freedom for a positive control (see §7).

class QNLPModel(ABC):
    name: str = "abstract"

        return self.decision_from_expvals(units[0]["expvals"])

    @abstractmethod
    def save(self, path) -> None: ...

    @abstractmethod

### `compose()` in detail

`compose(example, units)` receives, for one example and **one bond dimension**, a list of dicts aligned index-for-index with `audit_units(example)`:

```python
{"expvals": np.ndarray,   # one float per entry of unit.observables, in order
 "state":   np.ndarray,   # the (possibly truncated, always renormalised) 2**n statevector
 "n_qubits": int}
```

It must return **one integer label**. It is called once per chi (including `"full"`), so it must be pure/deterministic and reasonably cheap — it runs `len(examples) * len(chi_values)` times.

Three shipped composition styles, all legal:

- **Trivial** (`vqc_text`) — inherits the base `compose`, i.e. `sign(<Z_0>)`.
- **Classical head over per-token expvals** (`qsann`, `<repo>/src/simcert/models/qsann.py:258-278`) — 3 units per token (q/k/v), Gaussian attention computed in NumPy from the truncated expvals, then `sigmoid(w·m + b)`.
- **Reads `state` directly** — `qmsan` builds reduced density matrices from the truncated state (`reduced_density_matrix(units[3*t]["state"], n, keep)`), and `discocat` post-selects on the truncated amplitudes (`_postselect_readout(units[0]["state"], rec["post_select"], rec["open_wire"])`).

So a control's decision rule may be an arbitrary deterministic function of truncated expvals and/or truncated amplitudes.

### Torch-side head vs. `compose` must agree

`predict()` (used for `train_accuracy`, `val_accuracy`, and `delta_ent`) is the torch forward path; `compose()` on the untruncated state is the audit's `full_preds`. These are **two independent implementations of the same head** and they must agree numerically, or `tau_gen` and `full_accuracy` become inconsistent. `claqs.compose` handles this by pushing the expvals back through the *same* torch head:

```python
def compose(self, example, units: list[dict]) -> int:
    ev = torch.tensor(np.asarray(units[0]["expvals"], dtype=float), dtype=torch.float64)
    with torch.no_grad():
        return int(torch.argmax(self._logits_from_expvals(ev)))
```

**Copy this pattern.** Factor the head into a `_logits_from_expvals(ev)` used by both training and `compose`.

## 2. How `run_chi_sweep` truncates

`<repo>/src/simcert/audit/mps_truncation.py`.

### The truncation itself (`truncate_state_to_bond_dim`, line 49)

Not a bipartition — a **full left-to-right sequential-SVD MPS compression across every one of the `n-1` contiguous bonds**, on the flat dense vector, in qubit index order 0,1,…,n-1:

```python
tensors: list[np.ndarray] = []
residual = psi.reshape(1, -1)
bond = 1
for _ in range(n_qubits - 1):
    residual = residual.reshape(bond * 2, -1)
    u, s, vh = np.linalg.svd(residual, full_matrices=False)
    keep = int(np.sum(s > cutoff))
    if chi is not None:
        keep = min(keep, int(chi))
    keep = max(keep, 1)
    u = u[:, :keep]; s = s[:keep]; vh = vh[:keep, :]
    tensors.append(u.reshape(bond, 2, keep))
    residual = s[:, None] * vh
    bond = keep
tensors.append(residual.reshape(bond, 2, 1))
out = _contract_mps(tensors)
return normalize(out) if renormalize else out
```

Key facts:
- Every bond `k | k+1` for `k = 0..n-2` is capped at `chi`. Because the truncation is left-canonical-sequential and greedy, the result is the standard (not globally optimal, but the operational) chi-MPS approximation.
- `cutoff = 1e-12` (from `configs/audit/*.yaml`) discards vanishing singular values regardless of chi; **at least one is always kept**.
- The output is **contracted back to a dense 2^n vector and renormalised**. Downstream everything is dense.
- **Qubit ordering is load-bearing.** Bond dimension is measured across contiguous cuts in wire order. A state that is a product across cuts `{0,1}|{2,3}` but entangled between wires 0 and 3 will be cheap or expensive depending on how you assign wires. A positive control should deliberately entangle across *every contiguous* cut.

    num = np.abs(np.vdot(a, b)) ** 2

## 3. `chi_star()` and the three tolerances

`<repo>/src/simcert/audit/certificate.py:20-30`:

```python
def chi_star(accuracy_by_chi: dict, full_accuracy: float, tau: float) -> int | None:
    finite = sorted(k for k in accuracy_by_chi if isinstance(k, int))
    for c in finite:
        if full_accuracy - accuracy_by_chi[c] <= tau + 1e-12:
            return c
    return None
```

Smallest finite chi whose **accuracy against ground-truth labels** is within `tau` of the full-chi accuracy. `None` = no finite chi in the grid suffices.

The three tolerances, all set in `pipeline.py:91-97`:

```python
tau_gen = max(0.0, (train_accuracy - full_accuracy)) if train_accuracy is not None else 0.02
_, lo, hi = bootstrap_ci(labels, full_preds, metric=accuracy, n_boot=1000, seed=seed)
tau_ci = max((hi - lo) / 2.0, 1e-9)

finite = sorted(k for k in accuracy_by_chi if isinstance(k, int))
chi_star_agree = next((c for c in finite if agreement_by_chi[c] >= 0.95), None)
```

- **`tau_gen` — the generalization gap.** `max(0, train_accuracy − full_accuracy)`, where `train_accuracy` is `TrainReport.train_accuracy` (from `model.predict` on the train split) and `full_accuracy` is the compose-based test accuracy. Rationale: don't punish the surrogate for a loss smaller than the model's own train→test drop. **This is the tolerance the verdict uses.** Two failure modes for a control:
  - *Overfit control:* `train_acc = 1.0`, `full_acc = 0.80` ⇒ `tau_gen = 0.20`. A chi=1 surrogate at 0.62 would still count as `chi* = 1`. A memorising control is self-defeating.
  - *Well-fit control:* `train_acc ≈ full_acc` ⇒ `tau_gen = 0.0`, and chi* becomes hypersensitive — a single flipped test prediction pushes chi* up. Defensible only if the drop is large and stable.
  - Safe target: `train_acc ≈ full_acc ≈ 1.0` (so `tau_gen = 0`) **and** accuracy at sub-threshold chi at chance (≈0.5). Then chi* is robust under any tolerance you could argue for.
  - If `train_accuracy is None` (i.e. `mode=audit` without a fresh `fit`), `tau_gen` silently defaults to **0.02**.
- **`tau_ci` — statistical noise floor.** Half-width of the 95% example-level bootstrap CI (1000 resamples, seeded) on `full_accuracy` over the test set. Floored at `1e-9`. If `full_accuracy == 1.0` the bootstrap is degenerate (`lo == hi == 1.0`) and `tau_ci = 1e-9` — the strictest possible. At `n_test = 200, acc ≈ 0.9`, half-width ≈ 0.04.
- **`tau_agree` — label-free.** Smallest chi with `prediction_agreement(full_preds, preds_chi) >= 0.95`, i.e. the truncated surrogate reproduces the *model's own* predictions on ≥95% of test examples, regardless of correctness. `prediction_agreement` is `float(np.mean(y1 == y2))` (`fidelity.py:23`). This is the cleanest criterion for a control and the one a referee will find hardest to argue with, because it removes the label distribution entirely. **But it is not what drives the verdict.**

All three land in `cert.chi_star = {"tau_gen": ..., "tau_ci": ..., "tau_agree": ...}`.

**A positive control must beat the tolerance, not merely change the state.** The existing models prove the gap: `vqc_text` at n=8 has fidelity 0.284 at chi=1 — the state is destroyed — yet `accuracy_by_chi = {1: 0.565, ..., full: 0.565}` and `agreement_by_chi[1] = 1.0`. Every chi* is 1. Measured, from `results/metrics/sst2__vqc_text__*.json` (scaling sweep):

## 4. `classify_verdict()`

`<repo>/src/simcert/audit/certificate.py:17, 33-57`:

```python
SMALL_CHI = 4  # "chi* small" threshold (config-overridable)

def classify_verdict(
    chi_star_gen: int | None,
    delta_ent: float | None,
    baseline_gap: float | None,
    scaling_slope: float | None = None,
    small_chi: int = SMALL_CHI,
    ent_tol: float = 0.02,
    gap_tol: float = 0.02,
    slope_tol: float = 0.05,
) -> str:
    simulable_chi = chi_star_gen is not None and chi_star_gen <= small_chi
    ent_negligible = delta_ent is None or abs(delta_ent) <= ent_tol
    classical_ok   = baseline_gap is None or baseline_gap <= gap_tol
    flat_scaling   = scaling_slope is None or scaling_slope <= slope_tol

    if simulable_chi and ent_negligible and classical_ok and flat_scaling:
        return "CLASSICALLY_SIMULABLE"

    strongly_quantum = (chi_star_gen is None) or (
        chi_star_gen > small_chi and (delta_ent or 0.0) > 0.05
    )
    if strongly_quantum and not simulable_chi:
        return "QUANTUM_RESOURCEFUL"
    return "AMBIGUOUS"
```

Invoked from `SimCert.finalize_verdict()` (`certificate.py:85`) with **no kwargs** from the pipeline, so all four thresholds are at their defaults — `SMALL_CHI=4`, `ent_tol=0.02`, `gap_tol=0.02`, `slope_tol=0.05` — despite the "config-overridable" comment. It reads only `chi_star["tau_gen"]` (**not** `tau_ci`, **not** `tau_agree`), `delta_ent`, `baseline_gap`, `scaling_slope`.

Note the asymmetry: a **large** `baseline_gap` (quantum beats classical by >0.02) *blocks* `CLASSICALLY_SIMULABLE`. This is what makes 67 runs `AMBIGUOUS`.

### The exact route to `QUANTUM_RESOURCEFUL`

Two, and only two:

2. **`chi_star_gen > 4` AND `delta_ent > 0.05`.** Note the `(delta_ent or 0.0)` — if `delta_ent is None` (which is what `entanglement_removal: false` produces, as in `configs/audit/scaling.yaml` and `configs/audit/claqs.yaml`), this is `0.0 > 0.05 == False`, and you land in `AMBIGUOUS`, not `QUANTUM_RESOURCEFUL`. **A control audited under `scaling.yaml` cannot reach `QUANTUM_RESOURCEFUL` via route 2.**

Practical recipe: use a chi grid whose maximum is strictly below `2**(n//2)` so route 1 is reachable, **and** keep `entanglement_removal: true` so route 2 is also available and `delta_ent` corroborates. E.g. at n=12 (`exact = 64`), `chi_values: [1, 2, 4, 8, 16, 32, null]` gives six real truncation points and a reachable `None`.

## 5. The `delta_ent` entanglement-removal ablation

Built entirely in the **runner**, not the audit (`<repo>/src/simcert/runner.py:110-125`):

```python
if cfg.audit.get("entanglement_removal", True):
    twin_cfg = OmegaConf.merge(cfg.model, {"entangling": False})
    twin = get_model(cfg.model_name)()
    twin.build(twin_cfg, vocab)
    twin.fit(ds.train, ds.val, twin_cfg)
    twin_test_acc = _acc(labels_test, twin.predict(ds.test))
    full_test_acc = _acc(labels_test, model.predict(ds.test))
    delta_ent = full_test_acc - twin_test_acc
```

So: **a fresh instance of the same class, same seed, same hyperparameters, retrained from scratch with `cfg.entangling = False`, then compared on the test split by `predict()`** (not by `compose()`). `delta_ent = A_full − A_separable`. It is passed into `audit_model(..., delta_ent=delta_ent)` and stored verbatim; `twin_test_acc` also lands in `cert.meta["separable_test_accuracy"]`.

`OmegaConf.merge` **inserts** the `entangling` key even if the model's YAML never declares it. So the twin is always built. **If your model ignores `entangling`, `delta_ent` is just seed noise from a redundant retrain** — that is precisely what the existing numbers show: `qsann` `delta_ent ∈ [-0.161, 0.000]`, `qmsan` `∈ [-0.129, +0.065]`, `discocat` `= 0.0`.

The reference implementation of the flag is `vqc_text._apply_ops` (`<repo>/src/simcert/models/vqc_text.py:28-42`):

```python
def _apply_ops(qml, features, theta, n_qubits: int, n_layers: int, entangling: bool = True):
    """``entangling=False`` drops the CNOT ring -> a product-state ("separable") twin,
    which is exactly the entanglement-removal ablation (Axis B, Bowles et al.)."""
    for layer in range(n_layers):
        for i in range(n_qubits):
            qml.RY(features[i], wires=i)          # data re-uploading
        for i in range(n_qubits):
            qml.RY(theta[layer][i][0], wires=i)
            qml.RZ(theta[layer][i][1], wires=i)
        if entangling:
            for i in range(n_qubits):
                qml.CNOT(wires=[i, (i + 1) % n_qubits])
```

`qsann._template` does the same (drops the CNOT chain). Critically: the flag must be **read in `build()`, stored on the instance, persisted in `save()`/`load()`, and honoured on both the training path and the `audit_units()` export path** — `vqc_text` threads `self.entangling` into `_make_bound_qfunc` as well as `_qnode`, and writes it into `meta.json`. Miss any of these and the twin is not actually separable, or the audited circuit does not match the trained one.

### What a positive control must show

- **`delta_ent > 0.05` is the hard threshold** in `classify_verdict` (route 2). Aim well above it: full ≈ 1.0, separable at chance ≈ 0.5 ⇒ `delta_ent ≈ 0.5`. That is a two-line, referee-proof claim: *remove the entanglers and the model cannot learn the task at all.*
- `delta_ent` is measured through `predict()`, so `predict()` must be the real trained head, not a stub.
- Consistency check worth designing in: `accuracy_by_chi[1]` (product-state *truncation* of the entangled model) and `twin_test_acc` (separably *trained* model) should both sit near chance. They probe different things — post-hoc product approximation vs. product-state trainability — and agreeing is the strongest evidence.
- **Cost:** enabling `entanglement_removal` doubles training time (`fit` runs twice). Budget for it.

**Registration and discovery**

**Compute / memory budget (CPU-only, M5, 16 GB, <2.5 GB/run)**
- Training: `fit` backprops through `default.qubit` with `diff_method="backprop"`, float64. The autograd graph over the training set, not the 2^n statevector, is the binding constraint.   ```python
  chunk = getattr(cfg, "train_chunk", None)
  n = len(train)
  for _ in range(epochs):
      opt.zero_grad()
      if not chunk or chunk >= n:
          ...  # full-batch path
      else:
          for i in range(0, n, int(chunk)):
              part = train[i:i + int(chunk)]

              probs = torch.sigmoid(logits)

- Audit: `run_chi_sweep` keeps a **full dense state per chi value** in `sweep[k]["state"]`, and `pipeline` holds all units of one example simultaneously. Budget it; prefer **few units per example** for a wide control (ideally one whole-example unit, `claqs`-style).
- Grid driver `scripts/run_grid.py` enforces `--max-rss-gb 4.0` (kills the job) and `--min-free-gb 3.0` (gates the start), 2 workers, `nice 10`.

## 7. The design implication the numbers force

The instrument's blind spot is precisely located, and it is **not** the truncation math — that is correct and unit-tested (GHZ at chi=1 gives fidelity exactly 0.5 and `|<Z_0>| = 1` where the exact value is 0; product states at chi=1 are lossless; fidelity is monotone in chi — `tests/test_mps_truncation.py`).

The blind spot is that **`chi*` is defined on the label, and every audited model's label is a low-order function of *local, single-qubit* Pauli expvals**, which are exactly the quantities a product-state approximation gets roughly right. `vqc_text` reads `<Z_0>` alone; `qsann` reads `{Z_i, X_i, Y_i}` singles; `claqs` reads `{X_i, Y_i, Z_i}` singles. Hence fidelity collapses to 0.28 while agreement stays at 1.00.

A positive control therefore has to break that coupling. The levers the code actually exposes, in decreasing order of leverage:

1. **A readout that is a high-weight Pauli.** `observables` accepts `{0:"Z", 1:"Z", ..., n-1:"Z"}` — a global parity `<Z^{⊗n}>` — and `apply_pauli` computes it exactly at `O(2^n)` cost. A product-state MPS approximation of an entangled state can be forced to get a global parity badly wrong even when every single-site marginal is near-perfect. This is a one-line change relative to the existing models and is the single highest-leverage knob.
2. **A `compose` that is sharply nonlinear in the expvals**, so a small expval error crosses the decision boundary. The current heads are all smooth and slack.
3. **A state family whose Schmidt spectrum is flat with rank growing in n**, so the required bond dim scales as `2^{n/2}` rather than saturating at 2 (GHZ is rank-2 at every cut — maximally entangled by entropy but *cheap* for MPS, and chi=2 would suffice; do not build a GHZ-like control).
4. **A learning task the separable twin genuinely cannot fit**, so `delta_ent > 0.05` falls out of training rather than being asserted.

And the configuration constraints that make the result *expressible*: `n >= 8` (so chi=8 is a real truncation and `chi* > SMALL_CHI` is reachable), a chi grid whose maximum is strictly below `2**(n//2)` (so `chi* = None` is reachable), and `entanglement_removal: true` (so `delta_ent` is not `None` and route 2 of `classify_verdict` is open).
